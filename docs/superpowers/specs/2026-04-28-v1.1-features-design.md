# Capture One Date Plugin v1.1 — Design

**Date:** 2026-04-28
**Status:** Approved (pending user spec review)
**Builds on:** `2026-04-28-capture-one-date-plugin-design.md` (v1.0)

## Problem

v1.0 ships a single-date-applied-to-all workflow. Real photographers handle batches whose dates need different treatment: scans and exports often have the date hidden in the filename, film-roll scans need an evenly-spaced sequence, and a camera with the wrong clock needs every existing date shifted by the same delta. v1.1 extends the app from "one date" to "every row gets its own target date" while keeping v1.0's simple flow as the default.

## Goals

1. Allow per-row target dates with multiple auto-fill strategies.
2. Make timezones explicit and survivable across travel/region changes.
3. Add the supporting features that make a daily-driver app: presets, multi-select, undo, drag-drop, polish.

## Non-goals (v1.2+)

- Code-signing / notarisation (pending Apple Developer enrolment).
- Cloud preset sync.
- Linux / Windows ports.
- iPad / web versions.

## Solution overview

The v1.0 single date-picker is replaced by an **editable target-date column** in the file list. A **strategy bar** at the top auto-fills targets across all rows; users can override individual rows manually (sticky lock) or by per-row strategy override. A timezone picker controls the offset that's written alongside `DateTimeOriginal`. Presets save common configurations. Multi-select lets the user partially apply. An undo history restores per-file backups. The app also accepts files dragged onto the app icon, providing a Capture-One-free standalone path.

## Architecture

### Data model

```swift
struct EditableVariant: Identifiable {
    let info: VariantInfo                  // path, filename, currentExifDate (from v1.0)
    var targetDate: Date?                  // nil = skip this row on Apply
    var manuallyEdited: Bool               // user typed; resists strategy switches
    var strategyOverride: AutoFillStrategy?  // nil = inherit RootViewModel.defaultStrategy
    var timeZoneOverride: TimeZone?        // nil = inherit RootViewModel.defaultTimeZone
    var id: String { info.filePath }
}

enum AutoFillStrategy: Equatable {
    case sameDate(Date)
    case fromFilename(FilenamePatternConfig)
    case sequential(start: Date, interval: TimeInterval)
    case shiftBy(TimeInterval)
}

struct FilenamePatternConfig: Equatable {
    var customFormat: String?              // nil = built-in patterns only
}

struct Preset: Equatable, Identifiable {
    let id: UUID
    var name: String
    var defaultStrategy: AutoFillStrategy
    var defaultTimeZone: TimeZone
}
```

**Resolution chain** for any row's target date:

1. If `manuallyEdited` is true → use `targetDate` as-is.
2. Else if `strategyOverride` is non-nil → compute from that strategy with the row's TZ.
3. Else → compute from `RootViewModel.defaultStrategy` with the row's TZ.

Row TZ resolves the same way: `timeZoneOverride ?? defaultTimeZone`.

### New modules

| Module | Purpose |
|---|---|
| `Sources/AutoFill/AutoFillStrategy.swift` | The enum + a single `apply(strategy:to:timeZone:)` returning an updated `[EditableVariant]`. |
| `Sources/AutoFill/FilenameDateParser.swift` | Pure: filename → Date? via built-in patterns and an optional custom format. |
| `Sources/AutoFill/SequentialOrdering.swift` | Order-aware filler — applies start + N×interval to a manually-orderable row sequence. |
| `Sources/AutoFill/ShiftFiller.swift` | Each row's existing date += Δ; nil-date rows stay nil. |
| `Sources/Presets/PresetStore.swift` | UserDefaults-backed persistence for `[Preset]`. Single source of truth for save/load/rename/delete. |
| `Sources/Backups/BackupStore.swift` | Manages per-file `.c1dp-backups/` directories: write a backup before a write, list backups, restore, prune. |
| `Sources/FilesDropTarget/DroppedFileResolver.swift` | Pure: turn an array of dropped URLs (files or folders) into `[VariantInfo]` by recursively scanning for known image extensions. |

### Existing module changes

- **`ExifWriter`**: gains `writeCaptureDate(_ date: Date, timeZone: TimeZone, at url: URL)` that also writes `OffsetTimeOriginal` and `OffsetTimeDigitized`. The v1.0 overload remains and forwards with `.current`.
- **`DateOperation`**: `execute()` accepts `[EditableVariant]` (each carrying its own resolved target date and TZ) instead of a single `(date, variants)` pair. Per-row TZ is honoured by passing `variant.timeZoneOverride ?? defaultTimeZone` into the writer.
- **`CaptureOneBridge`**: unchanged interface — `readSelection()` still returns `[VariantInfo]`. `RootViewModel` lifts these to `EditableVariant` itself.
- **`RootViewModel`**: substantial reshape — owns `editableVariants`, `defaultStrategy`, `defaultTimeZone`, `selectedPreset`, `mode` (`.bridged` or `.dropped`), `tableSelection: Set<EditableVariant.ID>`, `history: [HistoryBatch]`.
- **`AppUI/`**: `SelectionListView` becomes `EditableVariantsTable` with editable Target column, lock badge, strategy-override badge, drag-handle (Sequential mode), and multi-select. New `StrategyPickerSection`, `TimeZoneFieldView`, `RowOverridePopover`, `PresetsMenu`, `HistorySheet`, `ModeToggle`, `DropZoneOverlay`.

## UX

### Window layout

```
┌────────────────────────────────────────────────────────────────────┐
│ [Refresh] [Mode: Capture One ▾] [Presets ▾] [History]   (toolbar)  │
├────────────────────────────────────────────────────────────────────┤
│  Auto-fill from:  [▾ Same date]  [Date picker ────────]            │
│  Time zone:       [▾ Europe/Berlin (+02:00)]                       │
│  ⚠ This range crosses a DST change (Sequential only)               │
├────────────────────────────────────────────────────────────────────┤
│   ⇅  Filename            Current        Target            Override │
│ ☑ ⇅  IMG_001.jpg         —              2024-06-12 09:00         ▸ │
│ ☐ ⇅  IMG_002.jpg         2019-03-15...  2024-06-12 09:00 🔒      ▸ │
│ ☐ ⇅  scan_a.tif          —              2024-06-12 11:00 ●seq    ▸ │
│ ☐ ⇅  random.jpg          —              —                        ▸ │
├────────────────────────────────────────────────────────────────────┤
│  All: 3 / 4 · Selected: 1 / 4   [Apply ▾]                          │
│  This modifies files in place. Back up first.                      │
└────────────────────────────────────────────────────────────────────┘
```

- **🔒** = manually edited; sticky across strategy switches.
- **●seq** = row has a strategy override (different from default).
- **▸** at row's right edge opens a per-row override popover.
- The handle column (⇅) is only visible/draggable in Sequential mode.

### Strategy bar

The default strategy popup drives the bulk of the table:

- **Same date** → one DatePicker.
- **From filename** → "Configure custom format…" button. Live counter: "Matched X / Y" (debounced 200ms while editing custom format).
- **Sequential** → start DatePicker + interval (number + unit popup: seconds/minutes/hours/days). Row reorder is enabled via the handle column. Inline DST warning when start + count×interval crosses a DST boundary.
- **Shift by Δ** → signed interval input (number + unit). Rows without an existing date stay at Target = nil.

Strategy/parameter changes recompute Target for every row that does NOT have `manuallyEdited` set.

### Time-zone row

- Picker populated from `TimeZone.knownTimeZoneIdentifiers`, defaulted to `.current`. Display format: `Europe/Berlin (+02:00)` with offset computed for "now" in the strategy bar; per-row overrides resolve their own offset against their target date (so DST is correctly handled per row).
- Help-text once: *"Time zone controls the offset written next to each photo's timestamp. Changing it doesn't shift the wall-clock dates in the table."*

### Editable table

- Each Target cell is editable inline. Editing flips `manuallyEdited = true` and renders 🔒.
- Clicking 🔒 clears `manuallyEdited` and recomputes the row from its strategy chain.
- Garbage text in a Target cell sets `targetDate = nil` and shows a red border until corrected; `manuallyEdited` stays true so the row doesn't snap back on focus loss.
- Right-click context menu per row (or on multi-select): `Lock`, `Clear locks`, `Clear targets`, `Restore previous version` (if a backup exists for this file), `Override row strategy…`.
- Multi-select via `Set<EditableVariant.ID>` bound to the table.

### Per-row override popover

Opened via the row's ▸ button or the context menu. Contents:

- Strategy chooser (or "Inherit default").
- The chosen strategy's parameters.
- TZ chooser (or "Inherit default").
- "Reset overrides for this row" link.

Closing the popover saves the override and recomputes the row's Target (if not manually edited).

### Mode toggle (bridged ↔ standalone drop)

Toolbar segmented control: **[Capture One]  [Drop files]**.

- **Capture One** mode: behaves as v1.0 — reads selection from a running Capture One, supports Refresh, surfaces empty/error states for permission denial and missing document.
- **Drop files** mode: the table empties; a drop zone fills the window. Drop files or folders to add them; folders are recursively scanned for image files (extensions: jpg, jpeg, tif, tiff, heic, png, gif, bmp). Same drop zone is also reachable via Finder → Open With or via dropping onto the app icon (registered in Info.plist). All strategies, presets, undo, multi-select work the same. Reload metadata is a no-op in this mode.

### Apply flow

- Footer shows two counters: All (X / Y where Y = total rows, X = rows with non-nil Target) and Selected (Z / W where W = currently-selected rows).
- Apply button is a popup menu: **Apply to all** and **Apply to selected** (latter disabled when nothing's selected).
- Pre-apply check: if any row's existing date differs from its (non-nil) Target AND was NOT manually edited, show the existing v1.0 overwrite confirmation sheet listing those rows. Manual edits skip the warning — they're explicit user intent.
- Per-row apply runs `ExifWriter.writeCaptureDate(target, timeZone: rowTZ, at: url)` then `FileDateWriter.setFileSystemDate(target, at: url)`.
- Backup: `BackupStore.captureBackup(of: url)` runs before each write, copying the original file to `.c1dp-backups/<filename>.<unix-timestamp>.bak` next to the original.
- After all writes, the batch is appended to `RootViewModel.history` and persisted (so undo survives app restarts).
- Results sheet unchanged from v1.0.

### Presets

- Toolbar **Presets ▾** menu: lists user presets, plus `Save current as preset…` (sheet for name input) and `Manage presets…` (sheet for rename/reorder/delete).
- Selecting a preset replaces `defaultStrategy` and `defaultTimeZone`. Per-row overrides and manual edits are NOT touched. The currently-active preset is shown checked in the menu.
- A v1.1 ships the **"Same date for all"** preset built-in; users can replace or augment.
- Persistence: `UserDefaults.standard` key `app.captureonedate.presets` stores the array as encoded JSON. Active preset id stored in a sibling key.

### History (undo) sheet

- Toolbar button **[History]** opens a sheet listing every Apply batch with timestamp, file count, and a summary line (e.g., "12 files · Same date strategy · Europe/Berlin").
- Expandable per-batch view: filename → before/after date.
- "Undo this batch" restores every backup in the batch atomically (`replaceItemAt` per file). Rows that have been written-to-since since are flagged ("Newer write exists for this file — skip / overwrite").
- Right-click on a single row in the table → "Restore previous version" if `.c1dp-backups/<filename>.*.bak` exists for that file; restores the most recent backup.
- Backup pruning: on app launch, walk every directory referenced by the history. Delete `.bak` files older than `maxAgeDays` (default 30) or beyond `maxSizeMB` per volume (default 1024). Settings live in Preferences → Backups.

## Strategies — details

### `sameDate`

The v1.0 behaviour. Every row's Target gets the picker's date. No per-row computation.

### `fromFilename`

`FilenameDateParser` first tries the user's `customFormat` (if set), then the built-in patterns in order. Returns nil if none match.

Built-in patterns (regex, all anchored to "anywhere in the filename"):
- `IMG_(\d{8})_(\d{6})` — most cameras.
- `DSC_(\d{8})_(\d{6})` — older Nikons.
- `IMG-(\d{8})-WA\d+` — WhatsApp.
- `(\d{4})-(\d{2})-(\d{2}) (\d{2})\.(\d{2})\.(\d{2})` — iOS Photos export.
- `(\d{4})-?(\d{2})-?(\d{2})` (date only) — fallback. Time defaults to 00:00:00.

The custom format uses standard date-format tokens (`yyyy`, `MM`, `dd`, `HH`, `mm`, `ss`) with `*` as a wildcard for any text:

- `Scan_yyyyMMdd_HHmmss_*.jpg` matches `Scan_20210315_142030_001.jpg`.
- Token compilation translates tokens to capture groups; `*` becomes `.*?`. Compilation errors surface inline in the strategy bar (red border, tooltip with the underlying error).

### `sequential`

Inputs: `start: Date` (a DatePicker), `interval: TimeInterval` (number + unit popup). Rows are filled in their *visual order in the table* — the user can drag rows to reorder via the handle column or move with Option+↑/↓.

Algorithm: row at visual index N gets `start + N × interval`. DST handling: each row's date is computed in the row's TZ for that specific date, so a Sequential range that crosses a DST boundary produces correct wall-clock times even though the literal seconds-since-1970 may have a non-uniform gap.

DST audit: when the computed range visibly crosses a DST boundary in the chosen TZ (i.e., the wall-clock seconds gap is not constant), an inline warning appears next to the interval field. Non-blocking.

### `shiftBy`

Each row's `info.currentExifDate` plus the signed `Δ` becomes the row's Target. Rows without a `currentExifDate` stay at Target = nil. Useful for "camera clock was 1 hour off" scenarios.

## Timezone awareness

- Default TZ resolves to `TimeZone.current` on launch.
- Per-row override via the row popover.
- The `ExifWriter`'s TZ overload writes:
  - `DateTimeOriginal` — the wall-clock date string in `yyyy:MM:dd HH:mm:ss` (unchanged from v1.0).
  - `OffsetTimeOriginal` — formatted as `±HH:MM`, computed from the picked TZ for the *target date*.
  - `OffsetTimeDigitized` — same value as `OffsetTimeOriginal`.
  - `TIFFDateTime` — same wall-clock string as `DateTimeOriginal`.
- For file formats where ImageIO can't carry `OffsetTime*` (rare; most modern containers support them), the writer logs a soft warning, omits those tags, and continues. The success result is unchanged.

## Error handling

| Case | Behaviour |
|---|---|
| Filename has no recognisable date | Target = nil; counter shows mismatch |
| Custom format fails to compile | Strategy bar inline red error, table unchanged |
| Sequential interval ≤ 0 | Inline validation, Apply disabled |
| `shiftBy` on nil-date row | Stay nil, gracefully skipped |
| Garbage text in Target cell | Red border, Target = nil, manuallyEdited stays true |
| `OffsetTimeOriginal` write fails | Fall back to `DateTimeOriginal` only; warn; success counted |
| Strategy switch loses user edits | Not a failure — manually-edited rows are sticky |
| Backup directory creation fails | Apply blocked for the affected file with `backupFailed` error; other files in the batch continue |
| Undo of a file that's been overwritten since the backup | Confirmation: "Newer changes exist. Continue? (overwrite / skip)" |
| Drop zone receives unsupported file types | Filtered silently; counter at the bottom shows "X files added, Y unsupported" |
| Drop zone receives folders | Recursive scan for known extensions; respects symlinks (no follow) |
| Drag-drop in C1 mode | Switches to Drop mode automatically; first dropped batch becomes the table |
| App launches with `--open` for files (Finder Open With) | Switches to Drop mode and adds those files |

### Atomicity

All write paths still use the v1.0 temp-file + integrity-check + atomic-replace pattern. The backup is captured BEFORE any temp file is created — so a backup exists for every file that is touched.

### Crash mid-batch

Already-written files have backups in `.c1dp-backups/`; the batch's history entry records up-to-the-crash progress. On next launch, history shows a partial batch tagged with a warning. User can complete-or-undo from there.

## Testing

### Unit tests (XCTest, no Capture One)

- **`FilenameDateParser`**: each built-in pattern (positive + negative); custom-format compilation errors; partial-name matches.
- **`SequentialOrdering`**: basic sequence; reorder before fill; DST-crossing range.
- **`ShiftFiller`**: rows with date / nil; positive and negative deltas.
- **`AutoFillStrategy.apply(...)`**: sticky-edit semantics; row-strategy-override semantics; resolution chain ordering.
- **`PresetStore`**: save / load / rename / delete; UserDefaults round-trip; corrupt data recovery (returns empty list, no crash).
- **`BackupStore`**: capture creates `.c1dp-backups/<filename>.<ts>.bak`; restore replaces the original atomically; pruning by age and size.
- **`DroppedFileResolver`**: file → VariantInfo; folder → recursive scan; unsupported types filtered.
- **`ExifWriter` (TZ overload)**: round-trip with non-local TZ; verify `OffsetTimeOriginal` written; format that doesn't support OffsetTime falls back gracefully.
- **`RootViewModel`**:
  - Strategy switch recomputes only non-locked rows.
  - Preset selection replaces default strategy/TZ without touching overrides.
  - Multi-select Apply only writes selected rows.
  - History batch persists and round-trips through UserDefaults.
  - Mode toggle clears table on switch from bridged to drop.

### Integration tests (run manually before release)

- Capture One round-trip with each strategy on real fixtures.
- Drop a folder of mixed JPEG/TIFF/HEIC/RAW; verify RAW rejected with `formatNotSupported` and others succeed.
- Time-zone smoke test: write file with TZ Asia/Tokyo, open the file in Preview on a Mac set to America/New_York, verify the displayed time corresponds to the original wall-clock + offset.
- Undo: write a batch, quit, relaunch, undo from history; verify file bytes match the pre-write `.bak`.
- Backup pruning: set max age to 0 days and confirm an older backup is removed on next launch.

## Migration / compatibility

- v1.0 users on upgrade get the same behaviour by default: the "Same date for all" strategy is the initial state.
- No on-disk schema changes for source files (EXIF tags are additive).
- Presets and history live in UserDefaults under namespaced keys; pre-existing UserDefaults remain untouched.

## Out-of-scope (parking lot)

- **Code-signing / notarisation** — pending Apple Developer Program enrolment.
- Cloud sync of presets.
- Linux / Windows / iPad ports.
- Plug-in-style integration into Capture One's UI (proven impossible in v1.0 research).

## Open questions for the planner

1. **Filename custom format DSL** — confirm that `yyyy/MM/dd/HH/mm/ss` + `*` is sufficient for v1.1, or whether photographers actually need 12-hour, AM/PM, locale-aware tokens.
2. **Drop-mode persistence** — should dropped file paths persist across app launches (so the user can come back to a session) or always reset on quit? v1.1 picks "always reset"; revisit if there's user demand.
3. **Backup directory location** — `.c1dp-backups/` next to source files works for typical photographer workflows. Consider a global preference for a single backup root for users whose source files live on read-only-ish volumes.
4. **History limits** — current plan is age + size. Should the user also see a per-batch max retention (e.g., last 100 batches)? v1.1 leaves this implicit (size pruning catches it).
